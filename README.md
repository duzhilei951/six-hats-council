# 六帽推演厅 · Six Hats Council

> 输入任一议题，六顶帽子依次登台，从事实、创意、价值、风险、直觉五个维度把它看透，最后由蓝帽收束成一份可执行的决策建议。专为 **Cherry Studio** 打造的平行思考决策工作台。

---

## 一、它解决什么问题

开会时最怕的场面：有人在报数据，有人在讲感觉，有人在挑毛病，还有人急着端新方案——四种脑袋同时运转，于是变成互相打断，吵半天没有结论。

六顶思考帽（Edward de Bono, 1985）用**平行思考**破解这个局面：把思考拆成六种模式，**同一时间只戴同一顶帽子**，一次只用一种脑袋。方向一致了，力气才不会彼此抵消。

本项目把这套方法论做成了一个点得动的小程序。

---

## 二、六顶帽子各管什么

| 帽子 | 管什么 | 戴上它只能说 | 典型问句 |
| :--- | :--- | :--- | :--- |
| 🧭 **蓝帽** | 流程与收束 | 组织顺序、总结、下一步 | "下一步戴哪顶帽？" |
| ⚪ **白帽** | 事实与数据 | 中立客观的信息，区分已知/未知 | "我们确切知道什么？还缺什么？" |
| 🟢 **绿帽** | 创意与可能 | 新点子、替代方案、反向做法（不许批评） | "还有什么别的办法？" |
| 🟡 **黄帽** | 价值与机会 | 好处、收益、最好情形（须有依据） | "这有什么好处？" |
| ⚫ **黑帽** | 风险与批判 | 哪里会出错、隐患、失败路径 | "哪里可能出错？" |
| 🔴 **红帽** | 情感与直觉 | 直觉、预感、情绪（**禁止给理由**） | "你的直觉是什么？" |

## 三、推演流程

```text
用户输入议题
    │
    ▼
① 🧭 蓝帽·开局规划 ── AI 判定议题性质，动态编排"本议题该用哪几顶帽 + 每顶帽的具体切入点"
    ▼
② ⚪ 白帽 → ③ 🟢 绿帽 → ④ 🟡 黄帽 → ⑤ ⚫ 黑帽 → ⑥ 🔴 红帽
    （串行推进，每顶帽子继承前面全部产出 —— 平行思考的累积效应）
    ▼
⑦ 🧭 蓝帽·收束合成 ── 输出【事实底座】【价值机会】【风险红线】【创意方案】【直觉信号】【决策建议】
    ▼
⑧ 本地留档 + 导出 Markdown / JSON
```

**两个设计要点**：

1. **蓝帽双开**——开场的蓝帽负责"设计该怎么思考"（让 AI 自己编排流程，而不是套死六顶全上）；收尾的蓝帽负责综合、找矛盾、给判断。
2. **顺序可变**——简单议题不必六顶全用，开局蓝帽会自动裁剪。这也符合 de Bono 本人的建议：*不要一次性用完所有帽子，可根据目标裁剪*。

## 四、安装与使用

### 方式 A：Cherry Studio 在线一键安装（推荐）
1. 打开 Cherry Studio 客户端；
2. 进入「小程序 / Mini Apps」管理器；
3. 点击「从网络安装」，输入托管清单 URL：
   ```text
   https://duzhilei951.github.io/six-hats-council/manifest.json
   ```
4. 确认权限授权后即可开箱即用。

### 方式 B：本地离线安装
在「小程序」页面点击「从本地安装」，选择仓库中的 `six-hats-council.miniapp` 即可。

### 使用步骤
1. 在输入框写下你的议题（或点上方模板快速填空）；
2. 点「开始六帽推演」，观察顶部六盏彩灯依次点亮；
3. 推演约需 1~3 分钟，可随时「终止推演」；
4. 完成后可导出 Markdown 报告，或在底部「历史推演档案」里回看。

## 五、技术说明

| 项目 | 说明 |
| :--- | :--- |
| **架构** | 单文件原生 HTML（CSS/JS 全内联），零构建依赖 |
| **算力** | 走 `cherry.ai.chat`，复用宿主已配置的模型，**无需填 API Key、不产生额外费用** |
| **网络权限** | **不需要** `network` —— 全程无外部请求，纯本地 |
| **权限清单** | `ai.chat` / `storage.*` / `clipboard.write` / `notification.show` |
| **数据存储** | 历史档案存于应用私有存储，最多保留 30 条，**数据不出本机** |
| **并发策略** | **串行推进**，同一时刻只有 1 个请求在飞，完全规避宿主并发上限 |
| **健壮性** | 双轨环境感知（浏览器可离线预览）+ 自愈式 JSON 解析 + XSS 转义 |

### 为什么用串行而不是并行？

Cherry Studio 宿主对每个应用有 **同时 2 个请求** 的并发上限。而六顶思考帽的精髓恰恰是"一次只用一种脑袋"——**串行既是方法论要求，又天然绕开了这道限制**，两者完美咬合。

## 七、发版流程（重要）

修改代码后发新版，**必须**用工具脚本重新打包，否则客户端升级会报
`Package hash mismatch: expected xxx, got yyy`：

```bash
# 1. 修改 manifest.json 里的 version（如 1.0.0 → 1.0.1）并同步 package.url 的版本路径
# 2. 一键打包 + 自动反填真实哈希
python .agents/skills/HA-miniapp-creator/scripts/package_miniapp.py . --release
# 3. 推送
git add . && git commit -m "release: v1.0.1" && git push
```

该脚本会自动压缩、计算真实 SHA-256 与字节大小、写回 `manifest.json`、归档到 `releases/<version>/`。
